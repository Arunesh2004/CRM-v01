## 4. Existing Components Reused
- **UI System**: The existing `bg-[#070B18] text-[#E7EAF5]` dark mode styling via Tailwind is uniformly preserved.
- **Primitives**: Reusing the robust `Button`, `Input`, `Card`, `Badge`, `dialog`, `textarea`, `Tabs` already implemented in `src/components/ui`.
- **Shell layout**: The Nexus CRM visual pattern found in `CRMLayoutClient.tsx` is completely reused for the shell implementation.

## 5. Authentication Integration
- Fully powered by `@clerk/nextjs`. The `<ClerkProvider>` wraps the root layout.
- Individual routes inherit `requireAuth()` server-side checks.
- User control exists globally in the header via `UserButton` combined with `useUser()`.

## 6. Tenant-Context Behavior
- **Deployment-per-company**: The architecture natively assumes one tenant deployment.
- Tenant context is read statically from `user?.tenant?.name` (falling back to "Organization") via the auth token and displayed prominently in the sidebar header.
- No "tenant switcher" was implemented because it violates the strict deployment-per-company design constraint.

## 7. Permission Behavior
- The sidebar restricts navigation elements based on `userRole` (`adminOnly` flags filter out System settings unless the user is in `ADMIN_ROLES`).
- **Security Check**: This frontend filtering is strictly for UX. All hard authorization runs in the Server Actions using `requirePermission()`.

## 8. Responsive Behavior
- Implemented natively by `CRMLayoutClient.tsx`.
- Sidebar retracts to a mobile drawer (`-translate-x-full`) on small viewports and toggles via a `Menu` icon button in the header.

## 9. Accessibility Considerations
- `lucide-react` icons are purely visual with accessible semantic text labels.
- Keyboard navigation is supported out-of-the-box by Shadcn components (using radix-ui).
