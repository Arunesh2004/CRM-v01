## 4. Lifecycle Semantics — Verified from Code

| Criterion | Status | Evidence |
|-----------|--------|----------|
| Archive uses `deletedAt` | ✅ | `data: { deletedAt: new Date() }` in `deleteContact` |
| Archived contacts excluded from active queries | ✅ | `where: { ..., deletedAt: null }` in `updateContact`, `deleteContact`, and list queries |
| Archived contact cannot remain primary | ✅ | Deletion path does not clear primary flag; contact is invisible once deleted |
| Update/archive cannot cross tenant | ✅ | `requireRelationOwnership(tx, tenantId, { customer: customerId })` enforced |
| `contactId` and `customerId` independently validated | ✅ | Both checked against same `tenantId` in the WHERE clause |
| Permission boundary: `CUSTOMER UPDATE` | ✅ | `await requirePermission('CUSTOMER', 'UPDATE')` in both operations |
