Security Architecture Corrections That Must Not Regress Tenant isolation uses application authorization plus PostgreSQL RLS; Prisma filters alone are not the sole boundary. Persistent CCTV processing is external to serverless routes. Workers use leases, fencing, stale-write rejection and node affinity. CCTV recordings follow upload → verify durable storage/integrity → confirm durable DB state → delete local source only after success. Webhook security includes authenticity/replay/idempotency controls. AI uses controlled application-side tools and authorization, never unrestricted database access. Optional providers degrade explicitly instead of crashing startup or fabricating success. Production certification is deployment-specific and evidence-based. 14. Credential and Secret Handling Credential handling was deliberately conservative throughout this rollout. The automated terminal could not access production secrets, so commands stopped rather than asking for secrets in chat or embedding them into uncontrolled files. Secret values are intentionally absent from this document. Production credentials are used only through intended secret stores or trusted provider dashboards. No production credential should be pasted into chat, source control, issue trackers or documents. Any credential historically exposed in an uncontrolled transcript is treated as compromised and should be rotated through the provider/deployment workflow. Client credentials belong only to the client's isolated deployment. Missing optional providers are represented as explicit capability/degradation states. Credentials do not imply provider compatibility; unsupported providers require an adapter or compatible contract. 15.
